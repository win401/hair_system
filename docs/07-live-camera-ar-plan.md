# 실시간 카메라 헤어 AR 계획

## 결론

사용자가 카메라를 켜고 고개를 돌리면서 헤어스타일을 탐색하는 기능은 제품 가치가
크다. 다만 생성형 이미지 모델을 영상의 매 프레임마다 호출하는 방식은 지연·비용·
얼굴 일관성 때문에 MVP에 적합하지 않다.

권장 구조는 다음과 같은 **하이브리드**다.

1. 실시간 카메라에서는 기기 안에서 얼굴과 머리 자세를 추적해 가벼운 2D/3D 헤어
   자산을 씌운다. 빠르게 여러 스타일과 각도를 탐색하는 용도다.
2. 사용자가 마음에 드는 스타일과 각도를 고르면 한 프레임을 촬영한다.
3. 선택한 장면만 현재 Gemini + Python 합성 파이프라인으로 보내 정밀 결과와 상담
   카드를 만든다.

실시간 화면은 `대략적인 형태·길이·볼륨 확인`, 정밀 생성 결과는 `얼굴에 자연스럽게
어울리는지 확인`으로 역할을 나눈다.

## 왜 이 방식인가

- 브라우저 카메라는 HTTPS에서 `getUserMedia()`로 사용할 수 있고 전면 카메라를
  우선 요청할 수 있다.
- MediaPipe Face Landmarker는 얼굴 랜드마크와 얼굴 변환 행렬을 제공하므로 머리의
  위치·크기·yaw/pitch/roll을 프레임별로 추적하는 기반으로 사용할 수 있다.
- Three.js는 WebGL에서 glTF/GLB 3D 자산을 렌더링할 수 있다.
- 카메라 프레임과 추적은 브라우저 안에서 처리하고, 사용자가 정밀 생성을 누른 한
  장만 서버로 전송할 수 있어 개인정보 설명도 단순하다.

참고:

- [MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)
- [MediaPipe Face Landmarker](https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker)
- [Three.js WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html)
- [Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)

## 단계별 구현

### 단계 0 — 카메라·추적 기술 스파이크

- `/camera` 베타 페이지
- 사용자 버튼을 누른 뒤 전면 카메라 권한 요청
- MediaPipe 얼굴 랜드마크와 자세를 로컬에서 추적
- 얼굴 중앙·크기·회전 디버그 가이드만 표시
- 카메라 중지, 권한 거부, 탭 이탈 시 트랙 해제

완료 기준:

- iPhone Safari와 Android Chrome에서 카메라가 열린다.
- 중급 스마트폰에서 체감 20fps 이상으로 얼굴 위치가 따라온다.
- 프레임은 서버로 전송되지 않는다.

### 단계 1 — 아이비리그 2D 필터

- 투명 배경의 정면 헤어 PNG 한 세트를 얼굴 랜드마크에 맞춰 Canvas/WebGL로 배치
- 머리 폭·높이·회전·색상 농도를 조절
- 좌우 회전이 커지면 `정면에 가까이 돌려주세요` 안내
- 스타일 변경, 전/후 비교, 화면 캡처

이 단계는 빠른 사용성 검증용이다. 정면에서는 유용하지만 옆모습으로 돌리면 평면
스티커처럼 보이므로 “다양한 각도 확인” 요구를 완전히 만족시키지는 못한다.

### 단계 2 — 2.5D 또는 3D 헤어

선택지는 두 가지다.

- **2.5D**: 정면·좌45도·우45도 PNG를 준비하고 얼굴 yaw에 따라 교차 전환한다.
  제작이 빠르지만 각도 전환과 귀·관자 가림이 부자연스러울 수 있다.
- **3D 권장**: 아이비리그 헤어를 GLB 메시로 제작해 머리 자세에 맞춰 회전한다.
  얼굴·귀 occlusion mask, 두상 크기 보정, 머리색 셰이더가 필요하지만 사용자가
  고개를 돌려 확인하려는 목적에는 가장 적합하다.

초기에는 아이비리그 스파이키 한 종만 구현하고, 실제 사용자 반응을 본 뒤 다른
스타일의 3D 자산 제작 여부를 결정한다.

### 단계 3 — 정밀 생성 연결

- 카메라에서 선택한 스타일·각도·캡처 프레임을 기존 위저드에 전달
- `정밀 결과 만들기`를 눌렀을 때만 Gemini API 1회 호출
- 최종 결과는 현재 원본 비교 슬라이더와 상담 카드에 그대로 연결

## 필요한 자산

현재 아이비리그 기준 사진은 생성 모델의 스타일 지시에는 유용하지만 실시간 AR
자산으로 바로 사용할 수 없다. 별도로 다음이 필요하다.

- 2D MVP: 얼굴이 제거된 투명 헤어 PNG, 정면과 필요 시 좌·우 45도
- 3D MVP: 두상 기준점이 정리된 GLB 헤어 메시, 검정·갈색 재질
- 스타일마다 앞머리선·관자·귀 주변 occlusion 기준
- 사용 권리 또는 직접 제작 권리가 명확한 자산

처음부터 모든 7종을 만들지 않는다. 아이비리그 스파이키 1종으로 카메라 사용률과
캡처→정밀 생성 전환을 확인한 뒤 확장한다.

## UX 제안

1. `사진으로 정밀 체험`과 `카메라로 빠르게 보기(베타)`를 나란히 제공
2. 카메라 권한 요청 전에 “영상은 기기에서 처리되며 저장되지 않음” 안내
3. 스타일 캐러셀로 즉시 전환
4. 고개를 천천히 좌우로 돌리라는 가이드
5. 마음에 드는 장면에서 캡처
6. `이 장면으로 정밀 AI 결과 만들기`에서만 유료 이미지 API 호출

## 파일럿 판단 기준

- 카메라 진입 사용자 중 권한 허용률
- 30초 이상 체험한 비율
- 스타일을 2개 이상 바꿔본 비율
- 카메라 캡처 후 정밀 생성으로 넘어간 비율
- 미용사 평가: 방향·길이·볼륨 상담에 실제 도움이 되는지

카메라 필터가 완벽한 사진 합성을 대체할 필요는 없다. 사용자가 여러 스타일을 빠르게
좁히고, 최종 한두 개만 정밀 생성하게 만들면 비용과 대기시간을 줄이는 탐색 도구로
충분한 가치가 있다.
